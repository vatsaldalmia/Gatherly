# Deploying Gatherly

Gatherly is a full-stack **TanStack Start** app. It builds to a **Cloudflare Workers**
module via Nitro, backed by **Cloudflare D1** (SQLite). Both are free tier. Google Maps
needs a billing account but stays free under the $200/month credit — cap the quota so you
can never be charged.

**Live:** https://gatherly.usegatherly.workers.dev
**Cost:** Workers $0 · D1 $0 · Google Maps ~$0 (under free credit).

---

## Architecture

| Layer        | Tech                                           | Where                            |
| ------------ | ---------------------------------------------- | -------------------------------- |
| Framework    | TanStack Start (React 19, Vite 8)              | `src/routes`, `src/lib/api`      |
| Server entry | Cloudflare `fetch()` handler                   | `src/server.ts`                  |
| Build        | Nitro `cloudflare-module` preset → `.output/`  | `vite.config.ts`                 |
| Database     | Cloudflare D1 + Drizzle ORM                    | `src/lib/db`                     |
| Auth         | better-auth (email/pw, Google, phone-OTP)      | `src/lib/auth`                   |
| Maps         | Google Maps (client render + server geocoding) | `src/lib/maps`, `src/components` |

`bun run build` runs Vite + Nitro, then `scripts/patch-wrangler.mjs`, producing:

- `.output/server/index.mjs` — the Worker
- `.output/server/wrangler.json` — generated by Nitro **every build**, then patched
- `.wrangler/deploy/config.json` — makes `wrangler deploy` pick up that generated config

## Gotchas that will cost you an hour (read this)

**1. Use `npx wrangler`, never `bunx wrangler`.** Under Bun, wrangler's *upload* step exits
silently with code 0 — no error, no deploy, and it swallows interactive prompts. It looks
like a mysterious no-op. Wrangler targets Node; this repo requires Node installed
(`brew install node`) purely for wrangler. Everything else (`bun run build`, `bun add`) is
fine under Bun.

**2. Nitro must be forced on.** `@lovable.dev/vite-tanstack-config` only auto-enables Nitro
inside a Lovable sandbox. Without the explicit `nitro:` block in `vite.config.ts`, a local
`bun run build` emits a Vite-only build with **no Worker at all**.

**3. Bindings are not on `process.env`.** Nitro's cloudflare preset does *not* forward `env`
to the server entry's `fetch`. It assigns `globalThis.__env__ = env` per invocation — that
global is the only way to reach the D1 binding. See `src/lib/cloudflare-env.server.ts`.
Plain string secrets *do* land on `process.env` (via `nodejs_compat`), which is why the rest
of the code reads them there.

**4. `compatibility_date` is pinned.** Nitro stamps it with today's *local* date, which
Cloudflare rejects as "in the future" whenever your clock is ahead of UTC. Pinned in
`scripts/patch-wrangler.mjs`.

**5. zod must stay on v4.** better-auth calls the v4 top-level `z.email()`. On zod v3 the
build still succeeds but auth throws `z.email is not a function` **in production only** —
dev resolves it correctly and hides the bug.

## One-time setup

### 1. Database — Cloudflare D1

```bash
npx wrangler d1 create gatherly     # put the returned id in scripts/patch-wrangler.mjs
bunx drizzle-kit generate           # schema -> drizzle/migrations/*.sql
npx wrangler d1 execute gatherly --remote --file=drizzle/migrations/0000_*.sql
```

### 2. Google Maps (free under credit — set a quota cap)

1. Google Cloud Console → new project → **enable billing** (required for a key).
2. Enable APIs: **Maps JavaScript**, **Geocoding**, **Places**, **Distance Matrix**.
3. Create a **browser key** (`VITE_GOOGLE_MAPS_API_KEY`, restrict by HTTP referrer) and
   ideally a separate **server key** (`GOOGLE_MAPS_API_KEY`, restrict by API, no referrer).
4. **Cap spend:** APIs & Services → Quotas → set low daily limits.

### 3. Secrets (stored on Cloudflare, never in the repo)

`wrangler secret` does not follow the deploy-config redirect, so it needs `--name`:

```bash
openssl rand -base64 32 | npx wrangler secret put BETTER_AUTH_SECRET --name gatherly
npx wrangler secret put GOOGLE_MAPS_API_KEY --name gatherly
npx wrangler secret put BETTER_AUTH_URL --name gatherly   # = your live https:// origin
# optional: GOOGLE_CLIENT_ID GOOGLE_CLIENT_SECRET TWILIO_ACCOUNT_SID TWILIO_AUTH_TOKEN TWILIO_PHONE_NUMBER
```

`VITE_APP_URL` is **build-time**, not a secret — it bakes into the browser bundle, so it must
be in `.env` before you build, and must equal the live origin.

## Deploy

```bash
bun run build      # Vite + Nitro + patch-wrangler
npx wrangler deploy
```

The first deploy on a fresh account prompts you to register a `workers.dev` subdomain
(one-time, account-wide, interactive — you must answer it in a real terminal).

---

## Local development

```bash
cp .env.example .env    # fill in values
bunx drizzle-kit push   # applies schema to a local dev.db file
bun run dev             # http://localhost:8080
```

Locally there is no Workers binding, so `getDb()` falls back to a SQLite file (`dev.db`).
Phone-OTP prints the code to the server console in dev (no SMS needed).

---

## Notes

- **Worker name** (`gatherly`) is pinned in `scripts/patch-wrangler.mjs`. Nitro would
  otherwise derive it from the git remote, which is still `plan-together`.
- **Observability** is enabled; `npx wrangler tail gatherly` streams live logs.
